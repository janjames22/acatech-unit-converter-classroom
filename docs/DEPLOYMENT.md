# Deployment

Unit Converter Classroom is a Flutter Web application. Vercel serves the static release generated by Flutter; it is not a Next.js, React, or Node frontend.

## Local Development

```bash
flutter pub get
flutter run -d chrome
```

Localhost is for development only. Use a public HTTPS preview for cross-device installation testing.

## Validation

Run before every deployment:

```bash
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
```

Do not deploy or commit a failing build.

## Production Build

```bash
flutter clean
flutter pub get
flutter analyze
flutter test
flutter build web --release
```

Verify that `build/web` contains at least:

- `index.html`
- `manifest.json`
- `favicon.png`
- `icons/`
- `flutter_bootstrap.js`
- `main.dart.js`
- `assets/`
- `canvaskit/`
- `pwa_install_bridge.js`
- `sw.js`

`build/` remains Git-ignored. The `.vercelignore` allowlist sends only `build/web` and `vercel.json` during a local CLI deployment, preventing source code, local reports, credentials, and caches from being uploaded.

## Git

Use `main` as the stable student-test branch. An optional future `dev` branch can hold ongoing work.

```bash
git status
git diff
git add .
git diff --cached
git commit -m "Describe the tested change"
git push
```

Before pushing, confirm the staged diff contains no `.env` files, service-account JSON, signing keys, certificates, passwords, tokens, student report data, or generated build output.

## Vercel

The repository's `vercel.json` configures:

- Framework preset: Other / Static.
- Output directory: `build/web`.
- Static-file-first behavior.
- Fallback of unknown application routes to `/index.html`.
- No-cache headers for the application shell and service worker.
- No serverless functions.

Vercel applies filesystem routing before rewrites, so real assets such as icons, JavaScript, WASM, fonts, the manifest, and the service worker are served normally. Only paths without a matching file fall back to Flutter's `index.html`.

### Preview deployment

Build locally, then create a non-production preview:

```bash
flutter build web --release
npx --yes vercel@latest deploy
```

If the CLI is logged out, a temporary claimable preview can be created with:

```bash
npx --yes vercel@latest deploy --temporary
```

Keep the real HTTPS URL returned by the CLI. Do not substitute localhost. Claim or link the project in the intended Vercel account before relying on it for ongoing student testing.

### GitHub-connected project

Do not configure Vercel's default Node build for this repository. Until a controlled Flutter-capable CI pipeline exists, continue the local-release-build CLI workflow. A future CI job may install the pinned Flutter version, run analysis/tests, build `build/web`, and deploy that verified output.

### Production deployment later

Only promote a tested preview after explicit approval:

```bash
npx --yes vercel@latest deploy --prod
```

The current task uses preview deployment only.

## Routing Verification

After deployment, request these paths directly and refresh them in the browser:

- `/`
- `/assessment`
- `/reports`
- `/converter`
- `/manifest.json`
- `/pwa_install_bridge.js`
- `/sw.js`
- `/icons/Icon-192.png`
- `/icons/Icon-512.png`

Application paths must return Flutter's `index.html`. Static resources must retain their correct content types and must not be rewritten to HTML.

The current Flutter shell uses internal indexed navigation rather than named URL routes. The fallback still protects future URL-based routes and direct test paths without creating lifecycle events inside Assessment Mode.

## Student Testing

### Android

1. Open the public HTTPS preview in Chrome.
2. Wait for Install App to become available.
3. Press Install App and accept the browser prompt.
4. Launch from the Home screen and verify standalone mode.
5. Confirm the Install App action no longer appears.

### iPhone and iPad

1. Open the public HTTPS preview in Safari.
2. Press Install App to view the manual instructions.
3. Use Share → Add to Home Screen → Add.
4. Launch from the Home Screen and verify standalone mode.

### Desktop

1. Open the HTTPS preview in Chrome or Edge.
2. Use Install App when the browser reports eligibility.
3. Launch the installed standalone window.
4. Verify converter, theme, Assessment Mode, and reports.

## Assessment Deployment Checks

1. Start an assessment intentionally.
2. Navigate between Home, Assessment, Reports, and converter screens; no incident should be created.
3. Trigger Install App during setup; the browser prompt must be suppressed from monitoring.
4. Leave the application, return, and confirm exactly one duration-based incident when supported.
5. Test screen-off/device-lock behavior on representative hardware.

Web lifecycle APIs cannot reliably distinguish every application switch, screen lock, call, or system dialog. Reports must retain neutral focus/visibility terminology.

## Bug-Fix Workflow

1. Fix the code on `dev` or a focused branch.
2. Run `flutter analyze`.
3. Run `flutter test`.
4. Run `flutter build web --release`.
5. Inspect the release package and staged Git diff.
6. Commit with a meaningful message.
7. Push to GitHub.
8. Create or update a Vercel preview.
9. Repeat the student/device matrix before promoting anything to production.
